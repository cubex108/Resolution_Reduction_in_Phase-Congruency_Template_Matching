# Python HOPC / RIFT comparison

These are transparent Python reimplementations, not certified reproductions of the authors' native binaries. Parameters and analysis were frozen before inspecting results from this new experiment. The original primary experiment remains unchanged.

## Algorithm provenance and scope

HOPC: Ye et al., *IEEE TGRS*, DOI [10.1109/TGRS.2017.2656380](https://doi.org/10.1109/TGRS.2017.2656380); [author repository](https://github.com/yeyuanxin110/HOPC), commit `bb0aa72e9cbaf70a9892a4bb709fd8ae435beb8f`. The implementation follows the paper's noise-compensated, frequency-weighted phase-congruency amplitude, odd-response orientation, unsigned orientation bins, trilinear voting and block L2 normalization. It uses 3-pixel cells, 3×3-cell blocks, eight orientation bins and 5-pixel block spacing, informed by the public wrapper. A Gaussian with sigma 1.5 pixels is centred on each cell; this width is an explicit implementation choice because the inspected paper does not specify it. No L2-Hys clipping is added. Normalized cross-correlation is computed on concatenated block descriptors. Descriptors are extracted from complete work images; their 9-pixel support can extend beyond the nominal template. Candidate origins still respect the same nominal template/search geometry and two-pixel grid as the scalar methods. This is **HOPC-Py+NCC in a common local search**, not the complete original feature-selection and registration pipeline. The old local HOPC class and the closed compiled MEX core are not used.

RIFT: Li et al., *IEEE TIP*, DOI [10.1109/TIP.2019.2959244](https://doi.org/10.1109/TIP.2019.2959244); [author repository](https://github.com/LJY-RS/RIFT-multimodal-image-matching), commit `7ea830e2f13cc3c226f975fe9e98b7666a8f26fb`. The target is the repository's **simplified no-rotation implementation**, not full rotation-invariant RIFT or RIFT2. Maximum phase-congruency moments supply a detection image; summed log-Gabor amplitudes supply the maximum-index map. The implementation preserves the inclusive 97×97 patch produced by the author's `patch_size=96`, the 6×6 cells, six orientation counts, MATLAB half-up rounding at cell boundaries, Fortran descriptor order and L2 normalization.

Disclosed RIFT port choices and repairs:

- OpenCV FAST 9-16, threshold 13 on the rounded 8-bit normalized moment map, replaces MATLAB `detectFASTFeatures(..., MinContrast=0.05)`. Nonmaximum suppression is enabled; up to 5,000 points are ranked by response, then row and column. Equivalence of these detectors is **not** asserted.
- L2 nearest-neighbour ratio threshold 1 rejects ties; each target descriptor is retained only for its first accepted source match. No additional absolute threshold is imposed. This approximates the permissive matching settings in the public example, not a claim of identical `matchFeatures` internals.
- An invalid-keypoint indexing typo is repaired by filtering the current point.
- Three-point affine consensus uses a 2-pixel threshold and a deterministic seed derived from pair and shift. Sampling includes the last match, rejects collinear triples and explicitly reports degenerate geometry. Confidence 0.999 provides adaptive stopping with at least 50 trials when combinatorially possible, capped at 10,000; best-consensus ties use residual sum, followed by least-squares refitting. These are disclosed changes to the release's FSC sampling and stopping, not parameter tuning on these images.
- No rotation normalization, corner-point augmentation, scale search or learned component is added. A three-inlier affine fit can still be incorrect; reported matching success is determined by the known test displacement, never by inlier count alone.

## Validation evidence

`validation.json` records 19 checks and the tested core hash. They cover odd/even image shapes and independent PhasePack complex-filter/moment agreement; constant inputs; contrast-inverted HOPC orientations; literal histogram/interpolation calculations; FFT correlation versus literal concatenated-vector NCC; MATLAB-style RIFT cell boundaries; invalid-point filtering; known affine recovery with outliers; degenerate geometry; translation coordinates; known synthetic translation; and RIFT self-matching. These establish mathematical and coordinate checks, **not benchmark accuracy or MATLAB output parity**. The fixed test seed is 481; benchmark seeds and parameters are in `protocol.json`.

## Experimental arms and denominators

1. Original prior-offset protocol: 122 pairs × six search-window offsets = 732 HOPC-Py+NCC observations. Original scalar results are read as frozen reference data.
2. Added image-translation protocol: the same 122 pairs × six integer translations × ten system/measure outputs = 7,320 observations. Target images are translated with zero fill and no interpolation; source images remain fixed. The four scalar strategies are raw, full PC, downsampled PC and MFPC, each with MI and CCRE. HOPC-Py+NCC and RIFT-Py affine complete the ten outputs. Search windows remain centred. Every method sees the same work images; RIFT uses global keypoints and affine geometry whereas the others use local translation search. This is a system-level comparison, not a representation-only causal contrast.

Known displacement is added to the datasets' nominal alignment, which has not been independently surveyed. Zero-filled boundaries and reduced overlap are part of the stress test. The common outcome is central-template-centre error; success requires a valid estimate and error below 3 pixels. RIFT also has a 5×5-grid transform RMSE over the geometrically overlapping source region. Missing, flat and degenerate outputs remain in the success denominator as failures; error summaries are conditional on valid outputs, with their denominator stated. A very poor but finite transform remains a valid output with a potentially large error. Success and error must be interpreted together.

Pair-level resampling keeps six shifts together. Intervals use 10,000 paired percentile bootstrap draws and are descriptive, unadjusted; the original 42 tests and their two Holm families are not expanded or rerun. SAR parent-scene dependence remains unknown. The new serial timing experiment uses the first five manifest pairs per configuration, three warm-ups and ten technical repetitions. Scalar timing jointly computes MI and CCRE, while each descriptor system computes one matcher; these are implementation-specific workload times, not language-independent algorithm speed claims.

## Reproduction and files

Use the frozen Python/library environment recorded in `protocol.json` for exact execution verification. In a fresh experiment directory, run `validate_python.py`, then `run_python_benchmark.py freeze`, `run_python_benchmark.py main --workers 3`, `run_python_benchmark.py timing`, and `summarize_python.py`. Inputs are the unchanged `results/crops/<pair_id>.npz` caches from the primary experiment. Source and cache hashes are checked; completed pair results are atomic and resumable. Concurrent-run wall time is diagnostic only. Do not alter frozen execution sources and reuse old results; create a separate version instead. Numerical re-analysis with `summarize_python.py` uses saved per-pair rows and primary zero-offset reference rows, without image caches or a matching machine fingerprint. Bootstrap seeds are fixed. Execution on another machine requires a separate, newly frozen experiment; never edit the old protocol to admit changed conditions.

The public/reviewer numerical archive may contain implementation code, protocol, validation and numerical observations. It must not include the downloaded reference PDFs, upstream MEX/PDB binaries or third-party image sets. Original provider images are not redistributed. The RIFT and Kovesi notices in `THIRD_PARTY_NOTICES.txt` must accompany the port.
